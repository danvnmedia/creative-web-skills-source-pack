## Broad discovery beyond the priority watchlist

Tiered capabilities, approvals and single-agent defaults mostly overlap existing
controls; no catalog or orchestration layer imported. Creation date was not established.

[ServiceNow/StarHarness](https://github.com/ServiceNow/StarHarness) was inspected as a
research lead. The retrieved primary page did not establish enough executable detail
or local benefit for promotion. No performance claim or implementation imported.

[Zetta-Embodiment](https://github.com/air-embodied-brain/Zetta-Embodiment) lists an
August 18, 2026 open-source milestone and September 10 integration activity. Its
physical-agent critics/recovery mechanism is adjacent research, not a demonstrated
benefit for this single coding-agent harness. No benchmark numbers adopted.

[SeoNaRu/nulnul-harness results](https://github.com/SeoNaRu/nulnul-harness/blob/main/evals/personal-evolution/results.json)

The public result file was not independently reproduced; no additional layer shipped.

[DeepSeek session-format discussion](https://github.com/deepseek-ai/deepseek-harness/discussions/5694),
September 5, 2026, is a concrete recovery/version-boundary failure report. It reinforces
preserving unknown source state rather than rewriting it. No provider-specific session
converter was imported; this release blocks unsupported operator-ledger schema.

[hatayama/codex-hooks](https://github.com/hatayama/codex-hooks) explicitly separates
command-hook replay from full host control semantics. It is a portability reference,
not an autonomous Skill activation sensor or approval/sandbox substitute.

## Version and promotion decision

The five approved mechanisms fit a v5.4-level expansion relative to 5.3.0, with trigger
truth and containment independently patch-worthy. The current canonical release
already reached 5.5.1, so the delivery is **5.5.2**, not a duplicate/downgrade 5.4.
No v6, extra agents, mandatory SDK, dashboard or duplicated Skill catalog is justified.
Measured token savings/causal completion gains remain NOT_RUN. New normal operation
adds no model calls; optional evals and audited security tests remain explicit.
