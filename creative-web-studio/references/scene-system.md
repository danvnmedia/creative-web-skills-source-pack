# Scene System

## Scene card
For each chapter capture: name, purpose, message, visual anchor, still frame, entry state, entrance, active behavior, scroll mode, interaction, exit, bridge, reduced motion, mobile, rendering method, assets, performance risk.

## Entrance families
- **Cut:** instant contrast, editorial rhythm.
- **Mask reveal:** discovery, concealment, controlled access.
- **Crop/scale continuity:** one element expands and changes role.
- **Depth push:** CSS perspective or 3D camera moves through structure.
- **Layer peel:** systems, hardware, construction, before/after.
- **Object continuity:** an image, letterform, line, dot, or product persists between scenes.
- **Assembly/disassembly:** explain parts and system relationships.
- **Typographic transformation:** type becomes mask, space, texture, or navigation.
- **Shader/material transition:** use only when the material behavior belongs to the concept.

## Active behavior
- Trigger: short reveal on entry.
- Scrub: progress maps to scroll; use for explanation or spatial traversal.
- Pin: preserve context while state changes; keep duration as short as the story allows.
- Pointer reactive: secondary depth only; never hide essential information behind pointer input.
- Drag: galleries, product rotation, comparison; provide touch and keyboard alternatives where meaningful.

## Bridge rule
Prefer continuity through shared object, crop, line, color, texture, grid, or camera motion. A page feels authored when scenes share logic.

## Intensity rhythm
Use 1–4 intensity:
1 = static/micro; 2 = reveal/parallax; 3 = pinned/scrubbed multi-element; 4 = WebGL/3D/shader/large media.
A strong page usually has many 1–2 scenes, fewer 3 scenes, and only a small number of 4 scenes.
